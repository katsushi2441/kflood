# Kurage 洪水・内水ハザードマップ (kflood)

住所を入れると、その地点が**洪水（河川の氾濫）で何メートル・何日浸かる想定か**と、
**内水（下水道・水路からの浸水）で何メートル浸かる想定か**を、データ時点つきで返します。

- デモ: https://kurage.exbridge.jp/kflood.php/（名古屋市版デモ ＋ 東京都・千葉県・神奈川県・静岡県）
- 洪水: 国土数値情報「洪水浸水想定区域（1次メッシュ単位）データ」(A31b) 国土交通省 — **全国**
- 内水: 地域ごとに出どころが違う。国の一括データが揃っていないため（A51 は9都府県10市区町村、重ねるハザードマップのタイルは66市町村）
  - **東京都** … 都建設局「浸水予想区域図」(CC BY) — 14区域・13ファイル・約687MB。**面ではなく約11mメッシュの点群**（1,639万点）。中小河川の外水氾濫と下水道の内水氾濫の両方
  - **名古屋市** … 市「内水氾濫ハザードマップ」なごや防災オープンデータカタログ (CC BY 4.0) — 浸水深と継続時間
  - **千葉県・神奈川県** … 国土地理院「重ねるハザードマップ」の内水タイル（PDL1.0）— 掲載のある市町のみ（千葉は船橋・柏・我孫子・八街・一宮の5市町、神奈川は横須賀ほか）
  - **静岡県は未収録**。重ねるハザードマップにタイルが無く、県のオープンデータからも内水のSHPが消えている（2026-09-21 実測）
- 高潮: 地域ごとに出どころが違う
  - **東京都・千葉県** … 国土数値情報「高潮浸水想定区域」(A49)。**配信は4都府県だけ**（東京・千葉・兵庫・福岡）。東京都はオープンデータ扱い、千葉県は条件付き公開（原則商用可）。**区分の文字列**で、継続時間は無い
  - **神奈川県** … 県オープンデータカタログ「高潮浸水想定等のGISデータ」(CC BY)。東京湾・相模灘の2沿岸、約5mの格子で**実測のメートル値**、**継続時間つき**（480万面）
  - **名古屋市** … 市の CC BY データ（継続時間つき）
  - **静岡県は未収録**。県の高潮浸水想定区域図は PDF のみ（2026-09-21 実測）
- 気象警報・注意報: 気象庁 防災情報（bosai）の JSON — **全国**。市区町村単位で、出ていないときは「発表されていません」と書く（`app/jma.py`）
- いま出ている避難情報: 名古屋市（学区）／東京都（町丁目）／千葉県・神奈川県（地区）／静岡県（市町）。都県が区市町村の発令を集約しているので、そこから読む（`app/alerts_ext.py`）。**静岡県は JSON API が公開されている**のでスクレイプしない。対象が「その町の一部」の発令は、そう書き分ける（町名が一致しただけで「対象です」とは書かない）

（リポジトリ・ポート・systemd unit の略称は `kflood`。対外の名前は「Kurage 洪水・内水ハザードマップ」）

## 地図で見る（/map/）
- MapLibre GL JS で、国交省「重ねるハザードマップ」の洪水タイル（想定最大規模・浸水継続時間・家屋倒壊、最新）、名古屋市 内水氾濫ハザードマップ（PostGIS → ベクタータイル `/tiles/naisui/{z}/{x}/{y}.pbf`）、学区線と現在の発令（`/api/gakku.geojson`）、国土数値情報A31（`/tiles/a31/...`、当社判定の元データ。最新との差を見るための切替）を重ねる。
- 地図クリック → `/api/check?lat=&lon=` で判定。タイルは `data/tiles/` にディスクキャッシュ（`scripts/warm_tiles.py` で名古屋分を先に生成）。
- 内水の収録範囲は座標で判定する（住所文字列に市名が無い地図クリックでも判定できる。2026-09-09 修正）。

## 設計の芯

1. **○×ではなく「何メートル・何日」を返す。** 0.5mと5mでは取るべき行動が違う。
2. **「区域外」と「未収録」を必ず区別する。** 取り込んでいない1次メッシュ・自治体で、黙って「区域外」と答えない（`meshes` 表・`naisui_coverage` 表で判定）。
3. **判定には必ずデータ時点と出典を添える。** `datasets` 表に時点が無いデータでは判定しない。
4. **近くに区域があるときは言い切らない。** 住所の座標は町丁目の代表点（khazard で実測 14〜50m のずれ）。250m以内に区域があれば地番での確認を促す。
5. **一次情報への導線を必ず返す。** 判定は参考であって公的な証明ではない。不動産の重要事項説明には自治体の図面そのものを使う。

## データ

| 項目 | 値 |
| --- | --- |
| 洪水 出典 | 国土数値情報 洪水浸水想定区域（1次メッシュ単位）A31 第4.0版 国土交通省 |
| 洪水 データ作成年度 | 2022年度（令和4年度）。配布ファイル日付 2023-06 |
| 洪水 収録 | **全国 1次メッシュ104件・21,375,145面**（洪水予報河川・水位周知河川＋その他の河川、配布151ファイル。2026-09-08 取り込み・83分） |
| 内水 出典 | 名古屋市 内水氾濫ハザードマップ（浸水想定 2022-05-27 指定・浸水継続時間 2023-03-07 掲載）CC BY 4.0 |
| 座標系 | JGD2011 地理座標系（EPSG:6668）。名古屋市データは EPSG:2449 から変換 |

土砂災害（khazard）の README に「洪水は2012年版しか無いので扱わない」と書いてあるのは**旧版（都道府県別 A31 v2.2）の話**です。
2021年以降に配布が始まった1次メッシュ単位版（第4.0版）は2015年水防法改正後の「想定最大規模」を含む現行基準で、本製品はこれを使います。

## 使い方

```bash
docker compose up -d                              # PostGIS（データ実体は KFLOOD_PG_DIR で別ディスクに置ける）
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
.venv/bin/python scripts/load_a31.py 5236 5237    # 1次メッシュ指定（名古屋周辺）
.venv/bin/python scripts/load_a31.py 23           # 都道府県コード
.venv/bin/python scripts/load_a31.py all          # 全国（数十分）
.venv/bin/python scripts/load_nagoya_naisui.py    # 名古屋市 内水
.venv/bin/python scripts/load_tokyo_naisui.py     # 東京都 浸水予想区域図（点群1,639万点・約20分）
.venv/bin/python scripts/load_a49_takashio.py     # 高潮 A49（東京都・千葉県）
.venv/bin/python scripts/load_kanagawa_takashio.py # 高潮（神奈川県・東京湾/相模灘・480万面）
.venv/bin/python scripts/load_gsi_naisui_tiles.py --pref 14  # 神奈川県 内水（重ねるHM）
.venv/bin/python scripts/load_nagoya_gakku.py     # 名古屋市 学区線（いまの避難情報に使う）
systemctl --user enable --now kflood.service      # または .venv/bin/uvicorn app.main:app --port 18386
curl 'http://127.0.0.1:18386/api/check?q=愛知県名古屋市中川区富田町大字千音寺'
```

`ogr2ogr`（GDAL）が必要です（Ubuntu: `apt install gdal-bin`）。A31 の GeoJSON は GDAL がストリーミングで読めるため、
431MB のファイルを 16 秒・常駐メモリ 120MB で取り込めます（2026-09-08 実測）。

## いまの避難情報（名古屋市版）

名古屋市の避難情報は「河川 × 対象学区」で出ます。`scripts/load_nagoya_gakku.py` で学区線（CC BY・268学区）を取り込むと、
`app/alerts.py` が市の災害情報配信ページから警戒レベル・種別・河川・発令時刻・対象学区の**事実だけ**を抽出し（市の文章は転載しない）、
判定・マイ・タイムライン・CSV一括に「いま、この学区に何が出ているか」を添えます。市のページを取得できないときは「取得できません」と返し、「発令なし」とは言いません。
2026-09-08 の実際の発令（24件・レベル5が3河川）を `tests/fixtures/` に固定してテストしています。

## 名古屋市の区・河川ページ（検索の受け皿）

検索は「天白川 氾濫」「名古屋 浸水」「中川区 避難所」のように河川名・区名で来るので、固定URLのページを持ちます。
`/nagoya/`（市ハブ）・`/nagoya/<区slug>/`（16区: 学区一覧・いまの発令・浸水のおそれ・対象河川・避難先）・`/river/<河川slug>/`（いまの発令・対象学区・発令履歴）・`/sitemap.xml`。
河川→対象学区の対応と発令履歴は `app/nagoya.py` が `data/alerts_history.sqlite` に貯め（初回は 2026-09-08 の実発令を種に）、区ごとの浸水のおそれは `scripts/ward_stats.py` が学区線に800点を打って推定して `ward_stats` 表に入れます（±3ポイント）。

## 他の自治体の内水を足す

`scripts/load_nagoya_naisui.py` の `DATASETS` に、その自治体の配布物（URL・属性名・座標系・出典表記・時点）を1件足して実行します。
判定は `naisui_coverage` の自治体名が住所に含まれるときだけ動くので、画面やAPIの変更は不要です。

## ほかのハザード判定とつなぐ（任意）

マイ・タイムラインは、内閣府「避難情報に関するガイドライン」（令和8年3月改定）に沿って
とるべき行動を出します。**自宅に留まる「屋内安全確保」を選べるのは洪水等・高潮だけ**で、
土砂災害・津波は立退き避難が基本です。そのため、洪水の想定だけでは答えを出しきれません。

次の環境変数を `.env` に書くと、同じ代表点について土砂災害・津波・指定緊急避難場所を
問い合わせ、判定と避難先に反映します。**既定は空（オフ）で、単体でも動きます。**

```
KFLOOD_KHAZARD_API=http://127.0.0.1:18376    # Kurage 土砂災害ハザードマップ
KFLOOD_KTSUNAMI_API=http://127.0.0.1:18380   # Kurage 津波浸水想定マップ
KFLOOD_KREFUGE_API=http://127.0.0.1:18378    # Kurage 避難所マップ
```

- 相手が落ちていても判定は止まりません（そのカードを出さないだけ。「該当なし」とは書きません）。
- 避難先は、その場所でいちばん重い災害（土砂＞津波＞洪水）に対応した場所だけを出します。

## 重要事項説明の災害項目（/juyo）

宅地建物取引業法施行規則 第16条の4の3 が定める災害の4項目を、住所ひとつで1枚にします。
**判定できるのは4項目のうち2項目だけです。** その事実を画面の先頭と紙の上に印字します。

| 号 | 項目（根拠） | 当社の判定 |
|---|---|---|
| 一号 | 造成宅地防災区域（盛土規制法45条1項） | **できない**（国のオープンデータに無い） |
| 二号 | 土砂災害警戒区域（土砂災害防止法7条1項） | できる（A33） |
| 三号 | 津波災害警戒区域（津波防災地域づくり法53条1項） | **できない**（国のオープンデータに無い） |
| 三号の二 | 水害ハザードマップにおける所在地（水防法施行規則11条1号） | 参考判定（条文は市町村の図面を指す） |

一号と三号は都道府県・市町村が個別に指定して公表しており、国土数値情報（137データセット）に
含まれていません（2026-09-18 に一覧を確認）。**黙って「該当なし」と書くと重説の誤りに直結する**ため、
「当社データなし」と印字して確認漏れを紙に残す設計にしています。

あわせて、別の号で説明が要る次の2つも同じ紙に載せます。
- 宅地造成等工事規制区域・特定盛土等規制区域（A56・kmorido）
- 災害危険区域（建築基準法39条・A48・kriskarea）

判定先は `.env` で指定します（未設定なら洪水・内水・高潮だけで出ます）。

```
KFLOOD_KHAZARD_API=http://127.0.0.1:18376
KFLOOD_KTSUNAMI_API=http://127.0.0.1:18380
KFLOOD_KMORIDO_API=http://127.0.0.1:18312
KFLOOD_KRISKAREA_API=http://127.0.0.1:18311
```
