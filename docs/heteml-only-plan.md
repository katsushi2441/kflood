# レンタルサーバー（heteml）だけで動かす形への移し替え（設計・2026-10-06）

閲覧のたびに当社のサーバー（PostGIS 35GB・FastAPI）へ問い合わせない。当社のサーバーは、データを作って1日数回まとめて送る裏方にする。

## 住所の判定（いまの /api/check）
- 位置：国土地理院の住所検索（msearch）。座標→市区町村の逆ジオコーダは止まることがある（2026-10-06 に応答なし）ので頼らない。
- 洪水：重ねるハザードマップの画像タイルを**ブラウザ（canvas）で読み**、その地点の色で判定する。タイルは `Access-Control-Allow-Origin: *`（2026-10-06 確認）。区域の無いタイルは 404。
  - 深さ（想定最大規模）`01_flood_l2_shinsuishin_data/{z}/{x}/{y}.png`。色（国交省「水害ハザードマップ作成の手引き」表3-2・詳細版を含む）:
    - 255,255,179 = 0.3m未満／247,245,169 = 0.5m未満（詳細版では0.3〜0.5m）／248,225,166 = 0.5〜1m
    - 255,216,192 = 0.5〜3m（詳細版では1〜3m。広いほうで答える）／255,183,183 = 3〜5m／255,145,145 = 5〜10m
    - 242,133,201 = 10〜20m／220,122,220 = 20m以上
  - 浸水継続時間 `01_flood_l2_keizoku_data`（凡例 shinsui_legend_l2_keizoku.png）:
    - 160,210,255 = 12時間未満／0,65,255 = 12時間〜1日／250,245,0 = 1〜3日／255,153,0 = 3日〜1週間
    - 255,40,0 = 1〜2週間／180,0,104 = 2週間以上／96,0,96 = 4週間以上
  - 家屋倒壊等氾濫想定区域 `01_flood_l2_kaokutoukai_hanran_data`・`_kagan_data`（赤 255,0,0 があれば区域内）
  - 国土数値情報（A31b）に入っていない愛知県の令和7年3月指定（植田川・堀川）も、こちらには入っている
- 名古屋市の内水・市の洪水ハザードマップ（当社だけが持つ CC BY データ）：名古屋市の範囲だけ当社で PNG タイルにして heteml に置き、同じくブラウザで読む。
  （重ねるハザードマップの内水 `02_naisui_data` は名古屋では取れなかった）
- PHP の GD は手元に無い。色はブラウザで読むので、サーバー側の画像処理は要らない。

## ページ
- 区・河川・発令の記録・使い方：感染症マップと同じく前もって HTML に書き出す（kkansen の app/export.py と同じ型）。
- 避難情報の「いま」：当社のサーバーが市のページを取り込み、変わったときだけ書き出して送る。
- 地図：当社のベクタータイル配信をやめ、地理院のタイル＋名古屋市の自前タイルを重ねる。
- CSV 一括判定：ブラウザで1行ずつ判定する（サーバーに送らない）。
